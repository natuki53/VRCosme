# VRCosme Classic 自動更新機能 設計書（Issue #12）

## 0. 現状ステータス（2026-07-29 時点）

> ユーザー向け名称は `VRCosme Classic` です。自動更新との互換性を保つため、リポジトリ、セットアップファイル名、User-Agent などの内部識別子は `VRCosme` を維持します。

- 自動更新機能は **実装済み**
- 起動時の更新チェックと更新通知ダイアログ (`UpdateDialog`) を実装
- 更新関連の設定は `settings.json` に永続化（`ThemeService` 経由で読み書き）
- 設定画面 `SettingsDialog` に「更新」タブが存在し、有効/無効・起動時チェック・プレリリース取得を切替可能
- 配布導線は GitHub Releases。README と `docs/index.html` で最新版リンクを案内
- インストーラー出力名は `VRCosme_Setup.exe`（Inno Setup: `Installer/VRCosme.iss`）
- バージョン表示は About 画面で `AssemblyInformationalVersion` を優先し、なければ `AssemblyVersion`
- 更新チェックの各段階を `LogService` に記録（取得・比較・スキップ・DL・起動）

## 1. 目的

VRCosme に「起動時の新バージョン検知」と「ユーザー主導での簡易更新導線」を提供し、手動更新の負担を下げる。  
対象 Issue: <https://github.com/natuki53/VRCosme/issues/12>

## 2. スコープ

### 2.1 実装済みの範囲

- 起動完了後（`MainWindow.Loaded`）に fire-and-forget で更新チェックを実施
- 安定版 / プレリリースの両方をサポート（設定で切替）
- 最新バージョンが現行を上回る場合に `UpdateDialog` を表示
- インストーラー (`VRCosme_Setup.exe`) を `%LocalAppData%\VRCosme\updates\` にダウンロード
- ダウンロード完了後、確認ダイアログを経てインストーラー起動 → アプリ終了
- 「スキップ」「後で」「リリースページを開く」の選択肢
- スキップしたバージョンは `SkippedUpdateVersion` に保存し再通知を抑止
- 通信・パース・比較・asset 不在などの失敗時はサイレント劣化（ログのみ）

### 2.2 未実装 / 将来検討

- 完全自動インストール（無人更新）
- 差分パッチ更新
- バックグラウンド常駐・定期チェック（`LastUpdateCheckUtc` は保存しているが起動時以外では未使用）
- ダウンロード進捗のパーセンテージ表示（現在は不確定（IsIndeterminate）プログレスバー）
- SHA-256 / Authenticode などの整合性・署名検証
- 「今すぐ確認」手動チェックボタン

## 3. 前提条件

- 配布は GitHub Releases を利用
- 公開リポジトリ: `natuki53/VRCosme`
- 期待 asset 名: `VRCosme_Setup.exe`
- アプリは WPF (`net10.0-windows`) 構成、設定は `%LocalAppData%\VRCosme\settings.json` に保存

## 4. 要件定義

### 4.1 機能要件（実装済み）

1. 起動後に自動チェックを行う（既定 ON、設定で OFF 可）
2. 更新がある場合、新旧バージョンとリリースノートを通知する
3. 「ダウンロードして更新」を選べる
4. ダウンロード完了後、インストーラー起動前に最終確認を行う
5. 「このバージョンをスキップ」「後で」「リリースページを開く」を選べる
6. スキップしたバージョンは次回起動時に再通知しない
7. プレリリースを通知対象に含めるかを設定で切替可能（既定 OFF）

### 4.2 非機能要件

- 起動体験を悪化させない（API タイムアウト 5 秒、UI スレッドをブロックしない fire-and-forget）
- 失敗時はサイレント劣化（アプリ本体機能は継続）
- ログで原因追跡できる（通信、パース、比較、DL、起動）

## 5. 取得元仕様（GitHub Releases）

### 5.1 参照 API

- 安定版のみ取得: `GET https://api.github.com/repos/natuki53/VRCosme/releases/latest`
- プレリリース含む取得: `GET https://api.github.com/repos/natuki53/VRCosme/releases?per_page=100`
  - `AutoUpdateIncludePrerelease == true` の場合に使用
  - 非 draft かつ semver パース可能なリリースの中から、最大バージョンを 1 件選択
  - 「安定版が beta より新しい」逆転状態でも検知できるようにするため、最新順ではなくバージョン最大値で判定する

### 5.2 HTTP クライアント設定

`GitHubReleaseClient.CreateClient()`:

- `Timeout`: 5 秒
- `User-Agent`: `VRCosme/1.0`
- `Accept`: `application/vnd.github+json`
- `X-GitHub-Api-Version`: `2022-11-28`

### 5.3 利用するフィールド

`GitHubReleaseInfo` / `GitHubReleaseAsset` に DTO 変換して保持:

- `tag_name`
- `body`（リリースノート）
- `html_url`（ブラウザ表示用）
- `prerelease` / `draft`
- `assets[]`（`name`, `browser_download_url`）

### 5.4 ダウンロード対象の選定ルール

優先順:

1. asset 名が `VRCosme_Setup.exe` と **大文字小文字を無視して一致**
2. 見つからない場合は `DownloadUrl = null` として、`UpdateDialog` の「ダウンロードして更新」ボタンを無効化し、「ダウンロードが見つかりません」を表示。`リリースページを開く` 導線は引き続き有効

## 6. バージョン比較仕様

実装: `Services/Update/VersionComparer.cs`

### 6.1 現在バージョンの取得

- `AssemblyInformationalVersion` を優先
- なければ `AssemblyName.Version` の `ToString()`
- どちらも取れない場合は `"0.0.0"`

### 6.2 比較ルール（SemVer 互換）

- 先頭の `v` / `V` を除去
- ビルドメタデータ（`+xxx`）は無視
- コアバージョンは `MAJOR.MINOR.PATCH[.REVISION]` を許容（1〜4 要素）
- プレリリース識別子（`-beta.1` 等）をサポート:
  - 数値識別子は数値として比較（先頭ゼロを正規化）
  - 数値と非数値が混在する場合は数値側を小さいとみなす
  - 同型は辞書順比較
  - 識別子数が少ない方を小さいとみなす（SemVer 2.0.0 準拠）
- プレリリースなし > プレリリースあり

### 6.3 出力

- `TryCompare`: 比較結果（負/0/正）と正規化された両バージョン文字列を返す
- `TryParseVersion`: `System.Version` 互換のコア部分を返す（プレリリース選定での順序付けに使用）

## 7. アーキテクチャ設計

### 7.1 構成コンポーネント（実装済み）

- `Services/Update/UpdateCheckService` (static)
  - チェック起点、オーケストレーション
  - `CheckForUpdatesOnStartupAsync(Window owner)` を公開
- `Services/Update/GitHubReleaseClient` (static)
  - Releases API 呼び出し、DTO 変換
  - 安定版 / 全リリース取得を内部で分岐
- `Services/Update/VersionComparer` (static)
  - SemVer 互換比較・正規化
- `Services/Update/UpdateDownloadService` (static)
  - インストーラーのダウンロードと保存、`Process.Start` でのインストーラー起動
- `Models/UpdateInfo`
  - 通知表示に必要な情報の集約（`CurrentVersion`, `LatestVersion`, `ReleaseNotes`, `ReleasePageUrl`, `DownloadUrl`, `HasDownload`）
- `Views/UpdateDialog.xaml(.cs)`
  - 更新通知 UI（モーダル）

### 7.2 既存への組み込み点（実装済み）

- `MainWindow.xaml.cs`
  - `MainWindow_Loaded` の末尾で `_updateCheckStarted` フラグを確認しつつ、`_ = UpdateCheckService.CheckForUpdatesOnStartupAsync(this);` を fire-and-forget 実行
  - 注: `App.xaml.cs` ではなく `MainWindow` から起動している
- `Services/ThemeService`
  - 更新関連の設定取得/保存 API を提供
- `Views/SettingsDialog`
  - 「更新」タブで設定値の編集 UI を提供

## 8. 設定項目（settings.json）

`Settings` クラス（`ThemeService.cs` 内）で管理:

| キー | 型 | 既定値 | 用途 |
|---|---|---|---|
| `AutoUpdateEnabled` | `bool` | `true` | 自動更新機能全体の有効/無効。OFF の場合、起動時チェックを行わない |
| `AutoUpdateCheckOnStartup` | `bool` | `true` | 起動時の更新チェック有効/無効 |
| `AutoUpdateIncludePrerelease` | `bool` | `false` | プレリリースも検知対象に含めるか |
| `SkippedUpdateVersion` | `string` | `""` | ユーザーがスキップしたバージョン（正規化後の文字列） |
| `LastUpdateCheckUtc` | `string` (ISO 8601 / `O`書式) | `""` | 最終チェック時刻（UTC）。現在は記録のみで定期チェックには未使用 |

補足:

- 後方互換は `Settings` クラスの既定値で吸収（古い `settings.json` でも安全に読み込める）
- `LastUpdateCheckUtc` はチェック開始直後に保存される（成否を問わない）

## 9. UI/UX 設計

### 9.1 更新通知ダイアログ (`UpdateDialog`)

表示条件（`UpdateCheckService.CheckForUpdatesAsync` 内）:

- `AutoUpdateEnabled == true` かつ `AutoUpdateCheckOnStartup == true`
- API 取得成功
- 取得したリリースが draft でない
- プレリリース取得が無効な場合、`prerelease == false`
- バージョン比較で `current < latest`
- `SkippedUpdateVersion` が正規化後の `latestVersion` と一致しない

表示内容:

- タイトル: `Update.Title`（例: `VRCosme - 更新`）
- 見出し: `Update.Heading`（例: `新しいバージョンがあります`）
- 現在版 / 最新版（`UpdateInfo` の `CurrentVersion` / `LatestVersion`）
- リリースノート: `Expander` で折りたたみ可（空のときは `Update.ReleaseNotesEmpty`）
- ステータス行: ダウンロード中は不確定プログレスバーと「ダウンロード中...」
- ボタン:
  - `ダウンロードして更新`（`DownloadButton`、`HasDownload == false` の場合は無効化）
  - `このバージョンをスキップ`（`SkipButton`、`SkippedUpdateVersion` を保存して閉じる）
  - `後で`（`LaterButton`、保存せず閉じる）
  - `リリースページを開く`（`OpenReleaseButton`、既定ブラウザで `ReleasePageUrl` を開く）

挙動:

- ダウンロード中は他ボタンを無効化（`SetDownloadingState`）
- ダウンロード成功後、`MessageBox` で起動確認 → `Yes` で `Process.Start(UseShellExecute = true)` → `Application.Current.Shutdown()`
- ダウンロード失敗時はエラー `MessageBox` を表示し、ダイアログは閉じない（再試行可）

### 9.2 設定画面（`SettingsDialog` の「更新」タブ）

`Settings.Section.Update` タブに以下のチェックボックスを配置:

- `更新機能を有効にする` (`AutoUpdateEnabledCheckBox`)
  - これが OFF の場合、配下 2 つは `IsEnabled = false`（`UpdateUpdateSettingsEnabledState()`）
- `起動時に更新をチェック` (`AutoUpdateCheckOnStartupCheckBox`)
- `ベータ版（プレリリース）も取得する` (`AutoUpdateIncludePrereleaseCheckBox`)

「今すぐ確認」ボタンは未実装。

## 10. シーケンス

1. アプリ起動 → `MainWindow_Loaded`
2. `_updateCheckStarted` が `false` のとき、`UpdateCheckService.CheckForUpdatesOnStartupAsync(this)` を fire-and-forget で開始
3. 設定確認: `AutoUpdateEnabled` と `AutoUpdateCheckOnStartup` が両方 ON でなければ即終了
4. `LastUpdateCheckUtc` を現在時刻で更新
5. `GitHubReleaseClient.GetLatestReleaseAsync(includePrerelease)` で最新リリース取得（タイムアウト 5 秒）
6. 失敗 / draft / 設定矛盾（プレリリース無効時に prerelease） → ログ出力して終了
7. `VersionComparer.TryCompare` で現行 < 最新を判定。比較不能 or 更新なし → 終了
8. `SkippedUpdateVersion` と一致 → 終了
9. asset から `VRCosme_Setup.exe` を探索（無ければ `DownloadUrl = null`）
10. UI スレッドで `UpdateDialog` を `ShowDialog`
11. ユーザーが「ダウンロードして更新」を選択:
    - `UpdateDownloadService.DownloadInstallerAsync(downloadUrl, latestVersion)` で `%LocalAppData%\VRCosme\updates\VRCosme_Setup_<version>.exe` に保存
    - ダウンロード中は他操作ロック、`.download` テンポラリ経由でアトミックに置換
    - 完了後、起動確認 `MessageBox`
    - `Yes` → `UpdateDownloadService.LaunchInstaller(path)` → `Application.Current.Shutdown()`

## 11. 例外・エラー処理

| 状況 | 挙動 |
|---|---|
| `AutoUpdateEnabled` または `AutoUpdateCheckOnStartup` が OFF | 何もしない（ログも出さない） |
| HTTP エラー / タイムアウト | `LogService.Error` に記録、通知なし |
| JSON パース失敗・例外 | `LogService.Error` に記録、通知なし |
| 最新リリースが draft / 設定矛盾の prerelease | ログのみ、通知なし |
| バージョン比較不能 | ログのみ、通知なし |
| 更新なし | ログのみ、通知なし |
| asset (`VRCosme_Setup.exe`) 不在 | ダイアログは表示、DL ボタンは無効化、`リリースページを開く` を提供 |
| ダウンロード失敗 | エラー `MessageBox` を表示、ダイアログは閉じない（再試行可） |
| インストーラー起動失敗 | `Process.Start` の例外は `Download_Click` の catch で `MessageBox` 表示 |

## 12. ログ設計

`LogService.Info` / `Error` への出力ポイント:

- `更新チェック開始`
- `更新チェック失敗: GitHub Releases 取得に失敗`
- `更新チェック失敗: HTTP {status} {reason}`
- `更新チェック: 最新リリースが対象外（draft/prerelease）`
- `更新チェック: バージョン比較に失敗`
- `更新チェック: 最新版なし`
- `更新チェック: スキップ済みのため通知省略 ({latestVersion})`
- `更新チェック: インストーラー asset が見つかりません`
- `更新チェック: 更新あり {current} -> {latest}`

機微情報（アクセストークン等）は出力しない。GitHub Releases の公開 API のみを利用し、認証ヘッダは付与しない。

## 13. セキュリティ考慮

実装済み:

- HTTPS のみ利用（`api.github.com` / GitHub の `objects.githubusercontent.com`）
- ダウンロード先はアプリ専用ディレクトリ `%LocalAppData%\VRCosme\updates\` に限定
- ファイル名は `Path.GetInvalidFileNameChars()` でサニタイズ
- 一時ファイル (`.download`) 経由でアトミック書き出し、失敗時はクリーンアップ

未実装の推奨拡張:

- asset への SHA-256 ハッシュ併記と照合
- Authenticode 署名検証
- 許可ホスト固定の明示チェック

## 14. 受け入れ基準（Definition of Done）

実装済み:

1. 起動時に自動チェックされる
2. 新バージョン時に通知ダイアログが表示される
3. `VRCosme_Setup.exe` をダウンロードできる
4. インストーラーを起動できる
5. スキップした版は再通知されない
6. 通信失敗時でもアプリ利用に影響しない
7. プレリリースの取得有無を設定で切替えられる

## 16. テスト観点

バージョン比較（`VersionComparer`）:

- `1.0.1` vs `1.0.2` → 更新あり
- `1.0.2` vs `1.0.2` → 更新なし
- `v1.0.2` の正規化（`v` 除去）
- `1.0.0` vs `1.0.0-beta.1` → 安定版が新しい
- `1.0.0-beta.1` vs `1.0.0-beta.2` → 後者が新しい
- 4 要素版 `1.0.0.0` のパース
- ビルドメタデータ `1.0.0+abc` の無視

API 異常:

- タイムアウト（5 秒）
- 404 / 403 / 5xx
- `assets` 欠損
- プレリリース取得時のフォールバック（最大バージョン選定）

asset 異常:

- `VRCosme_Setup.exe` 不在時の DL ボタン無効化と `リリースページを開く` のみ動作

操作:

- スキップ保存後の再起動で再通知されない
- より新しい版が出れば `SkippedUpdateVersion` と不一致になり再通知される
- ダウンロード後の起動確認で `No` を選んだ場合、アプリは終了しない

設定連動:

- `AutoUpdateEnabled` OFF で起動時チェック自体が走らない
- 「更新機能を有効にする」OFF 時、配下 2 つが無効化される

## 17. 未決事項 / 既知の制約

1. 「後で」を選んだ場合の再通知は次回起動時に毎回行われる（当日抑止などはなし）
2. 定期チェック（n 時間ごと等）は未対応。`LastUpdateCheckUtc` を保存しているのみ
3. ダウンロード進捗は不確定プログレスバー。バイト数ベースの%表示は未実装
4. インストーラー実行前の未保存作業確認は行わない（アプリ終了時の確認は `MainWindow_Closing` 側で実施）
5. 「今すぐ確認」手動チェックボタンは未実装
6. SHA-256 / 署名検証などの整合性チェックは未実装
