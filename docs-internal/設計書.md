## 1. このアプリは何？

VRCosme は、VRChat などで撮ったスクリーンショットの色味や明るさを整えるための Windows アプリです。読み込み → 補正 → 比較 → 書き出し、までを 1 つの画面で完結できるようにしました。

特長は次の点です。

- AI を使って「人物」「服」「髪」など特定の部分だけを選んで、その部分にだけ補正をかけられる
- AI モデルはネットからダウンロードして使うので、アプリ本体は軽い
- AI 処理はパソコンの中で完結する（画像をどこかにアップロードしたりはしない）

### 1.1 主な機能

- 13 種類の補正（明るさ、コントラスト、ガンマ、露出、彩度、色温度、色かぶり、シャドウ、ハイライト、明瞭度、シャープ、ぼかし、周辺減光）
- 比率を選んで切り取り（1:1, 16:9, 9:16, 4:3, 3:4, 3:1, 自由, なし）
- 90 度回転、左右・上下反転
- Before / After / 分割スライダーでの比較表示
- マスク機能（手で塗る、色で選ぶ、AI に任せる、SAM でクリックして選ぶ）
- 元に戻す／やり直し（最大 20 回）
- 作業の保存と再開（`.vrcproj` という独自フォーマット）
- PNG / JPEG の書き出し（JPEG は品質指定あり）
- 5 言語対応（日本語 / 英語 / 韓国語 / 中国語簡体字 / 中国語繁体字）
- ライト／ダーク／システム連動のテーマ
- 起動時に GitHub の新バージョンをチェックして通知

### 1.2 規模

- C# のコード: 約 61 ファイル、合計 11,000 行くらい
- 一番大きいのは画面定義の `MainWindow.xaml`（約 94 KB）
- 配布は単体の `.exe`（ライブラリも全部入りの形）

## 3. アプリ全体の作り

### 3.1 MVVM という方針

WPF でよく使われる「画面とロジックを分けて書く」方針です。次の 3 つに分けています。

- **View（画面側）**: 見た目だけを担当する。XAML とコードビハインド。
- **ViewModel（橋渡し）**: ユーザーの操作を受けて、画像を加工したり保存したりする。画面が表示する値もここに持つ。
- **Model（データ）**: 補正値やマスクなどのデータの形を定義しただけのクラス。

イメージ図:

```
┌─────────────────────────────────────────────────┐
│ View（XAML + コードビハインド）                   │
│  MainWindow.xaml / Crop.cs / Mask.cs / Zoom.cs   │
│  ダイアログ各種                                    │
└─────────────────────────────────────────────────┘
            ↕ DataBinding（自動で値を同期）
┌─────────────────────────────────────────────────┐
│ ViewModel（MainViewModel）                       │
│ ファイルが大きくなるので機能ごとに 7 つに分けた:    │
│  ・コマンド（ボタン押下時の処理）                   │
│  ・画像処理（プレビュー生成）                       │
│  ・マスク処理                                      │
│  ・Undo/Redo                                     │
│  ・セッション保存                                   │
│  ・プロパティ変更時の連動                           │
└─────────────────────────────────────────────────┘
       ↕ 呼び出す
┌──────────────┬───────────────┬─────────────────┐
│ Pipeline     │ AI Services   │ その他の Services │
│ 補正処理を    │ ONNX Runtime  │ 設定保存、ログ、   │
│ 段階で実行    │ で AI を動かす │ 多言語、更新確認   │
└──────────────┴───────────────┴─────────────────┘
       ↕ 使う
┌─────────────────────────────────────────────────┐
│ Models（データの型だけを定義したクラス）             │
│  AdjustmentValues / MaskLayer / EditState など    │
└─────────────────────────────────────────────────┘
```

### 3.2 矢印の向き（依存関係）

- View → ViewModel → Service / Model の順で、上から下へしか呼び出さない
- Pipeline や Service は画面に依存していないので、画面が変わっても再利用できる
- Model は何にも依存していない（一番下）

これを守ることで「画面を作り直しても中の処理は使い回せる」状態になります。

### 3.3 自分が意識した方針

| 方針 | 具体的に何をしたか |
|---|---|
| データは 1 ヶ所に集める | 編集中の値はすべて `MainViewModel` のプロパティに置いた |
| 状態のコピーは書き換え不可にする | 元に戻す用のスナップショットは `record` で作って、後から変えられないようにした |
| 補正処理は段階に分ける | 1 個ずつ独立したクラスにして、順番を 1 ヶ所で管理する |
| 設定や更新はアプリ全体から使うので、共通の場所に置く | `static class` の Service にまとめた |
| 通信や I/O が失敗してもアプリは止めない | catch してログだけ残し、機能を続行する |
| 大きなクラスはファイルを分ける | `MainViewModel` は 7 ファイル、`MainWindow` は 5 ファイルに分割 |

### 3.4 起動時にやっていること

```
App の OnStartup
  ├ 言語設定を読み込む
  ├ テーマを適用（ライト/ダーク）
  ├ ログの初期化（フォルダ作成、起動ログ書き込み）
  ├ セッション保存フォルダを準備
  └ 例外ハンドラを 3 種類登録
       ・どこで例外が出てもログには残るようにする

MainWindow の Loaded
  ├ 右パネルの幅を復元
  ├ オーバーレイ（グリッド、ルーラー、マスク表示）を初期化
  └ アップデート確認を裏で開始（待たずに次へ進む）
```

## 5. 画像補正の仕組み

### 5.1 値を 2 段階で管理している理由

スライダーで動かす値（-100〜100 など）と、画像処理で使う値（明るさなら 1.0 が変化なしの倍率）は単位が違います。混ぜると混乱するので、間に変換用のメソッドを 1 つだけ置いています。

- `AdjustmentValues` … スライダーの値（人間が見るほうの値）
- `AdjustmentParams` … 画像処理用の値（プログラムが使うほうの値）
- 変換は `AdjustmentValues.ToParams()` だけ

### 5.2 補正は順番に並んだ「ステップ」を流す

`Pipeline/PipelineRenderer.cs` で 5 つのステップを順に実行します。

```csharp
private readonly IReadOnlyList<IAdjustmentStep> _steps =
[
    new PixelAdjustmentsStep(),  // 露出→温度→明るさ→コントラスト→シャドハイ→ガンマ→ビネット
    new SaturationStep(),        // 彩度
    new ClarityStep(),           // 明瞭度
    new BlurStep(),              // ぼかし
    new SharpenStep(),           // シャープ
];
```

各ステップは「効果がゼロに近ければ何もしない」を最初にチェックして、無駄な計算を省いています。

### 5.3 PixelAdjustmentsStep の中身

1 回のループで 8 種類の補正を順番にかけています。シャドウとハイライトは、その画素の明るさによってどれくらい効かせるかを変えています。

```csharp
// 画素の明るさ（人間の目の感度に近い重み）
float lum = r * 0.2126f + g * 0.7152f + b * 0.0722f;
// 暗い場所ほど大きい重み、明るい場所ほど大きい重み
float shadowW    = (1 - lum) * (1 - lum);
float highlightW = lum * lum;
float tonalAdj   = shadowAmt * shadowW + highlightAmt * highlightW;
```

周辺減光（ビネット）は、中心からの距離を 0〜1 にして、その 2 乗をかけています。中心は明るく、端ほど暗くなります。

### 5.4 明瞭度の計算（ClarityStep）

「元画像 − ぼかし画像」を強調する古典的な方法です（アンシャープマスクと呼ばれます）。ぼかしの半径は画像の幅で決めて、解像度が違っても自然な強さになるようにしています。

### 5.5 マスクと混ぜる

特定の領域だけに補正をかけたいときは、補正後の画像と元の画像を、マスクの値（0〜255）で混ぜます。

```
new_pixel = original_pixel + (adjusted_pixel - original_pixel) * (mask / 255)
```

- mask が 0 のところは元画像のまま
- mask が 255 のところは補正後の画像そのまま
- 途中の値はブレンドされる

### 5.6 マスクのフチをなめらかにする処理

マスクが手描きや AI 生成だとフチがガタガタになります。それを目立たなくする処理を自分で書きました。

1. マスクのフチからの距離を BFS で計算する
2. その距離に応じて、フチ付近だけ 0〜255 の値をなだらかにつなぐ（smoothstep 関数を使用）
3. その後でぼかしを 2 回かけてさらに馴染ませる
4. 内部（フチから十分離れたところ）は念のため 255 に戻して、補正効果が薄まらないようにする

### 5.7 プレビューと書き出しで何が違うか

スライダーを動かすたびにフル解像度で再計算するのは重いので、編集中は最大 1920px に縮小した画像でプレビューしています。書き出しのときだけ、フル解像度の元画像に同じ処理を最初からやり直します。

これで「軽い操作感」と「画質を落とさない書き出し」の両方を実現しています。

## 6. マスク機能

### 6.1 マスクの持ち方

マスク 1 枚は `byte[]` の配列で持っています。画素 1 個につき 1 バイト（0 または 255）です。フチをなめらかにする処理を通したときだけ、中間の値が入ります。

複数のマスクをレイヤーのように重ねられて、レイヤーごとに「どんな補正をかけるか」を別々に設定できます。

### 6.2 マスクの作り方は 5 種類

| 方法 | 中身 |
|---|---|
| 手で塗る（ラッソ） | 画面上をドラッグした点を集めて、その内側をマスクにする |
| 色で選ぶ | クリックした点と似た色のところを、4 方向に広げて選んでいく |
| AI（全体） | U²-Net などのモデルに画像を渡して、被写体を自動検出 |
| AI（クリック） | クリックした座標を起点にして、AI の結果を絞り込む |
| SAM クリック | MobileSAM という AI でクリック位置から細かい部位を選ぶ |

### 6.3 既存のマスクとの混ぜ方

新しい選択結果をどう既存のマスクに反映するかも 4 通り用意しています。

- **置き換え**: 完全に上書き
- **マージ**: 既存マスクに接している部分だけ取り込む（離れたゴミは無視）
- **追加**: 単純に OR でつなぐ
- **削除**: 消しゴム（既存マスクから削る）

### 6.4 回転や反転をするとマスクも一緒に動く

画像を 90 度回したり反転したりすると、マスクも全レイヤー分だけ同じように回します。これをやらないと、補正対象がズレてしまいます。

### 6.5 マスクのフチを画面に表示する

選択中のマスクのフチを、白い破線で画面にうっすら描画しています。毎フレーム計算すると重いので、マスクが変わるたびに 1 回だけ計算して、結果をキャッシュするようにしました。

## 7. AI を使った領域選択

### 7.1 2 種類の AI を併用

| 種類 | モデル | 何ができるか |
|---|---|---|
| SOD（顕著オブジェクト検出） | U²-Net、IS-Net、Silueta | 「写真の中の主役」をまるごと選ぶ |
| プロンプト型 | MobileSAM | 「ここの部分だけ選んでほしい」をクリックで指定 |

### 7.2 SOD のやっていること

1. 画像を 320×320 に縮小する
2. AI の規格に合わせて色を正規化（平均値・標準偏差で割る、よくある前処理）
3. AI に渡して、画素ごとの「主役らしさ」のマップを受け取る
4. **オプション**: 画像を反転させて 4 回（普通、左右反転、上下反転、両方反転）推論して平均する → 精度アップ
5. しきい値を Otsu 法（自動で良いしきい値を見つけるアルゴリズム）で決める
6. しきい値で切ってから、小さなノイズを取ったり、穴を埋めたりして整える

### 7.3 SAM のやっていること

SAM は「画像を AI 用に変換するエンコーダ」と「クリック位置から領域を出すデコーダ」の 2 つに分かれています。

工夫したのは、同じ画像なら 1 回目のクリックで作ったエンコーダの結果をメモリに保存しておいて、2 回目以降はデコーダだけ動かすところです。これで「クリックするたびに重い」が「2 回目以降は一瞬」になります。

画像を変えたり回転・反転したりしたときは、保存しておいた結果が古くなるので捨てます。

### 7.4 AI モデルはあとからダウンロード

アプリ本体に AI モデルを同梱するとサイズが膨らむので、初回利用時にネットからダウンロードする方式にしました。

- 保存先: `%LocalAppData%\VRCosme\Models\`
- 一時ファイル（`.download`）に保存してから名前を変える → 途中で失敗してもゴミが残らない
- 1 MB 以下のファイルは「壊れている」と判定して使わない

### 7.5 CPU か GPU かを選べる

設定で CPU か GPU（DirectML）を選べます。GPU を選んだのに失敗したときは、自動で CPU に切り替わるようにしてあります。

## 8. 元に戻す／やり直し（Undo/Redo）

### 8.1 「ある瞬間の編集状態」を 1 つの型にまとめている

`EditState` という型に、その時の編集状態を全部まとめて入れます。

- 13 個の補正値
- 切り取り枠の位置とサイズ、選択中の比率
- 回転（0/90/180/270）、左右反転、上下反転
- マスクのリスト（マスクごとの補正値も含む）

これを `Stack` に積んでいくのが基本です。

### 8.2 上限は 20 回

マスクのデータは画像サイズに比例して大きいので、無限に積むとメモリを食います。上限を 20 にして、超えたら古いものから捨てています。

### 8.3 スライダーを触る前にスナップショットを取る

「Undo に積むタイミング」は次のルールで決めています。

- スライダーの場合: マウスのボタンを押した瞬間にスナップショットを 1 個取る
- マスクの操作の場合: 操作開始前に 1 個取る
- 一部のスライダー（プリセットの強さ等）は Undo に積みたくないので、`Tag="NoUndo"` を付けて除外している

### 8.4 状態を戻すとき

Undo を押すと、現在状態を Redo スタックに積んでから、Undo スタックの一番上を取り出して、それを画面に反映します。

戻すときは「補正値を一気に書き換える → 画像の回転反転をやり直す → マスクを書き戻す → クロップを反映」の順で進めて、最後にプレビューを 1 回だけ更新します。途中で何回もプレビューが走らないようにフラグでガードしています。

### 8.5 未保存マーク（*）の判定

タイトルバーに `*` が出ていれば未保存です。判定は単純ですが、Undo で「保存した時の状態」に戻ったら自動で `*` を消すようにしています。「画像との差分が本当にあるか」を毎回チェックしています。

## 9. 作業の保存と読み込み

### 9.1 ファイル形式

拡張子は `.vrcproj`、中身は JSON です。テキストエディタで開けば中身が読めるようにしてあります。

### 9.2 入っているもの

`SessionDocument` というクラスがそのまま JSON になります。

- 元画像のパス（絶対パスと相対パスの両方）
- 13 個の補正値

`ドキュメント\VRCosme\Sessions\` を起動時に作っておいて、保存ダイアログの初期フォルダにしています。ファイル名も元画像から自動で生成されます。

`SessionDocument.Version` を増やせば良いだけにしてあります。読み込み側で「自分より新しいバージョンは開けません」というエラーも出せるようにしてあります。

## 10. プレビュー表示の工夫

### 10.1 画像を 3 段階で持つ

メモリ上で同じ画像を 3 種類持っています。

| 名前 | 役割 |
|---|---|
| `_pristineImage` | 読み込んだ時のオリジナル。回転反転すらかけていない。 |
| `_transformedImage` | オリジナルに回転と反転を反映したもの。書き出しのもとになる。 |
| `_previewSourceImage` | プレビュー用に最大 1920px に縮小したもの。 |

複数のスレッドから触るので、アクセスは全部ロックして守っています。

### 10.2 連続したスライダー操作を「最後だけ」処理する

スライダーをドラッグすると 1 秒間に数十回イベントが飛んできます。1 回ずつ画像を再計算すると重いので、次のような仕組みにしました。

```
スライダー変化 → 「次回更新が必要」フラグを立てる
                  ├ もし更新処理が既に走っているなら、何もしない
                  └ 走っていなければ:
                      while フラグが立っている限り
                          フラグを下ろす
                          プレビューを 1 回更新する
```

これで「ドラッグ中の動きは追わなくていい、ドラッグを終えた時点の値で 1 回計算してくれれば良い」を実現しています。

### 10.3 重い処理は別スレッドで

UI スレッドを止めないために、画像処理は `Task.Run` で別スレッドに逃がしています。WPF の `WriteableBitmap` は `Freeze()` してから ViewModel に戻すと、UI スレッドへ安全に渡せます。

### 10.4 メモリリーク対策

`Image<Rgba32>` は使い終わったら `Dispose()` しないとメモリを解放しません。`try/finally` を徹底して、途中でエラーが起きても確実に解放されるようにしています。

## 16. ログとエラーへの対応

### 16.1 ログファイル

- 場所: `%LocalAppData%\VRCosme\logs\VRCosme_yyyy-MM-dd.log`
- 1 行 1 メッセージで、頭にタイムスタンプと INFO/ERROR が付く
- 7 日より古いログは起動時に自動削除
- 設定からまとめて ZIP に書き出して提出できるようにしてある

### 16.2 例外ハンドラ

`App.OnStartup` で 3 種類の例外ハンドラを登録しています。

| ハンドラ | 何に対応する |
|---|---|
| `AppDomain.UnhandledException` | スレッド外で起きた例外 |
| `DispatcherUnhandledException` | UI スレッドで起きた例外 |
| `TaskScheduler.UnobservedTaskException` | await し忘れた Task で起きた例外 |

すべてログに残し、UI スレッドの例外のみユーザーに MessageBox で通知します。

### 16.3 アプリ内のエラーへの基本方針

- 画像読み込み失敗 → エラーダイアログを出してステータスバーをエラー表示に
- プレビュー失敗 → ログだけ残してアプリは止めない
- 設定保存失敗 → 黙って無視（次回起動時は初期値に戻るだけ）
- AI モデルの DL 失敗 → エラーダイアログ＋再試行可能
- GPU 初期化失敗 → CPU に自動切替

## 17. プライバシーへの配慮

- 画像処理も AI 推論もすべて自分の PC の中で完結する
- アプリから外に出る通信は次の 3 種類だけ
  1. 更新確認のための GitHub API
  2. 更新インストーラーのダウンロード
  3. AI モデルの初回ダウンロード
- 認証トークンなどは一切送信しない
- ログ、設定、モデル、セッションファイルはすべてユーザーのローカル PC にのみ保存

## 付録 A. スライダーを動かしてから画像に反映されるまで

```
ユーザーがスライダーを動かす
        ↓
MainViewModel の OnBrightnessChanged → SchedulePreviewUpdate()
        ↓ （短時間に連続した変化はまとめられる）
UpdatePreviewAsync()
        ↓
プレビュー用の縮小画像を Clone する
        ↓
別スレッド（Task.Run）で：
  ImageProcessor.ApplyAdjustments()
    → PipelineRenderer が 5 ステップを順に実行
       ・PixelAdjustmentsStep
       ・SaturationStep
       ・ClarityStep
       ・BlurStep
       ・SharpenStep
  マスクが有効なら、各マスクレイヤーごとに：
    ImageProcessor.ApplyAdjustments(マスクあり) で結果を合成
  ImageProcessor.ToBitmapSource() で WPF が表示できる形式に変換
        ↓
UI スレッドに戻して、PreviewBitmap に代入 → 画面に反映
```

書き出しの時は、縮小画像ではなくフル解像度の画像に対して同じ処理を最初からやり直し、最後に切り取り → PNG/JPEG 保存、という流れになります。
